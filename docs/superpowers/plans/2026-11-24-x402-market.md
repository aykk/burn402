# x402 Market Pivot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn burn402 into a purchasing agent that scans x402 compute sellers, picks the best fitting plan inside a spending limit, pays over x402 and rents a machine, with no model training in the flow.

**Architecture:** A new `lib/market/` module holds pure logic (catalog parsing, chooser, payment guard), a seller HTTP client for one wire protocol, a purchase journal, a local test seller that speaks the same protocol and settles on Solana devnet, and a `MarketRun` state machine. The session, API routes and the main page are rewired to it. The real seller (`compute.x402layer.cc`, mainnet) and the test seller differ only in base URL, network and wallet.

**Tech Stack:** Next.js 16.4.6 (read `node_modules/next/dist/docs/` first), React 19, Tailwind v4, TypeScript strict, Vitest, `@x402/core|fetch|svm` 2.26 (do not upgrade), `@solana/kit`, `node:crypto`.

**Spec:** `docs/superpowers/specs/2026-11-24-x402-market-design.md` — read it; it holds the verified wire facts (endpoints, 402 shape, auth message template).

## Review Focus

- **Paying twice.** A paid request that times out, answers 5xx, 202 or 409 `settlement_pending` must never lead to a second signed payment for the same run. (Tests in Task 4 and Task 7.)
- **Seller changes the deal between quote and payment** (higher amount, different token, different network). The guard must refuse before signing. (Task 3, Task 7.)
- **Server restart with a paid machine alive.** The journal must let the next start find and destroy it. (Task 5, Task 8.)
- **Feeds that are down, empty or shaped differently** (missing `hourly`, `ram` as string, plan with no `locations`, nuza `gpus: []`). Parsing must skip bad rows, not crash the scan. (Task 1.)
- **Nothing fits** (need larger than any plan, or every plan over the limits). The run must end `refused` with counts by reason, not hang or pick an over-limit plan. (Task 2, Task 7.)

Behavior the tests pin:
- `quote` POSTs `/compute/provision` with body `{ plan, region, os_id, label: "agent-rental", prepaid_hours, ssh_public_key, network: "solana", max_total_usd }` and **no** auth or payment headers. `os_id` is `2284` for vultr; for digitalocean `"ubuntu-24-04-x64"`; omitted for runpod. `prepaid_hours` is the candidate's `hours` (integer). The exact JSON string is kept in `Quote.body` and reused byte-for-byte by `provision`. A 402 with a decodable header gives a `Quote`; a 409 with `quote_usd` → `QuoteError PRICE_CAP`; a body mentioning stock/unavailable/capacity (case-insensitive) with 4xx/5xx → `OUT_OF_STOCK`; other non-402 → `SELLER_ERROR`; fetch throwing → `UNREACHABLE`; 402 without a readable requirement → `NO_402`. The accepted requirement is the first `accepts` entry whose network starts with `solana:`.
- `provision`: (1) POST `Quote.body` unpaid again to get a **fresh** 402; (2) call `pay(required, accepts)`; if it returns `{ refused }` → `not_charged REFUSED_BY_GUARD` and no further request; (3) POST the same body with the returned headers. Outcomes: 200/201 with `order` → `active` (or `pending` when `order.status` is not `"active"` or there is no `ip_address`); 202 → `pending` with the order; 409 containing `settlement_pending` → `unknown`; 402 → `not_charged PAYMENT_REJECTED`; 409 with `quote_usd` → `not_charged PRICE_CAP`; 5xx or a thrown fetch → **resend the identical request with the identical headers** up to 2 more times with `sleep(2000)`, then `unknown`. `pay` is called **at most once** per `provision` call, always.
- `instance/instances/destroy` send `authHeaders` for the exact path (no query string) and body `""`. `instances()` accepts either a bare array or `{ instances: [...] }` / `{ orders: [...] }`. Instance mapping: `id`, `status`, `ip_address` → `ip` (empty string or `"0.0.0.0"` → `null`), `expires_at` ISO → epoch seconds, `plan`, `region`. `instance(id)` returns `null` on 404. `destroy` treats 404 as success and throws on other non-2xx. Without a signer these three throw `Error("a wallet is needed to manage machines")`.

- `POST /compute/provision` unpaid → 402 with `PAYMENT-REQUIRED` header built by `processor.paymentRequiredHeader` for the price `hourly × hours × surcharge`, bumped by `faults.quoteBumpPct` percent on **every second and later** unpaid call for the same body (so the quote differs from the fresh 402). Respects `max_total_usd` (409 `{ error, quote_usd }`). Region in `outOfStockRegions` → 503 `{ error: "plan is out of stock in <region>" }`. `wrongAsset` → the header's asset is replaced with `So11111111111111111111111111111111111111112`. Unknown plan → 400.
- Paid → `processor.decode` + `verify` + `settle`. Verify failure → 402. `fail5xxOnce` → the first paid call answers 503 **before** settling and clears the flag. `settlementPending409` → settle, create the machine, answer 409 `{ code: "settlement_pending" }`. `pending202` → settle, create, answer 202 `{ pending: true, order }`. Otherwise 200 `{ success: true, order: { id, plan, region, status, ip_address, expires_at }, tx_hash }`. A repeated paid request with the same `PAYMENT-SIGNATURE` header returns the same order and does not settle again. The machine's `owner` is the settlement's payer. `status` is `"pending"` with `ip_address: ""` until `activeAfterSec` (default 3) has passed, then `"active"` with an IP `203.0.113.N`.
- `GET /compute/instances`, `GET /compute/instances/:id`, `DELETE /compute/instances/:id` require valid `X-Auth-*` (via `verifyAuth`) and only show the caller's machines (401 bad auth, 404 not found/not theirs). List returns `{ instances: [...] }` without destroyed ones. Reused nonces within the skew window are rejected (401).
- `POST /compute/_faults` (test-only control, accepts a partial `Faults`, returns the current ones) — only honored when the request's `Host` is `127.0.0.1:*` or `localhost:*`.
- The route file is thin: `const s = getTestSeller(); if (!s) return 503 JSON; return s.handle(request)` for GET/POST/DELETE, `export const dynamic = "force-dynamic"`.

Rules:
- `scanning`: `seller.catalog()` and, when given, `spotFeed()`; each becomes a `sources` row; a failed source is `ok: false` with its message. Both failing → `failed`.
- `choosing`: `choose(...)`. `ranked` empty → `refused` with `refusal.code "NOTHING_FITS"`, `leftOut` filled from `summarize`, one `onRecord` with `outcome: "refused"`.
- `quoting`: walk candidates in order; for each, try its regions in order (at most 3 regions per candidate); collect up to 3 successful quotes, give up after 8 failed quote attempts. Each attempt is logged in `attempts`. Quotes over the limits (run them through `checkPayment` with `approvedAtomic` = their own amount) are marked `quote failed` with the guard's reason. Choose the lowest `amountUsd`. No quote → `failed` with the last reasons.
- `approval`: always on the real market; on the test market only when `askBeforePaying`. `approval.code` from `newCode()` (default 16 random hex bytes). `approve` with a wrong code, in a wrong phase, or twice → `{ ok: false }` and nothing happens.
- `paying`: **journal `intent` first**, then `seller.provision(quote, pay)` where `pay` runs `checkPayment({ accepts, market, approvedAtomic: BigInt(quote.atomic), budgetLeftUsd: limits.budgetUsd, rateUsdHr, hours, alreadyPaid, payTo: quote.accepts.payTo })`; a refusal returns `{ refused }`, sets `refusal`, emits a `refused` record and journals `failed`. `payer` null → `failed` "no wallet is set up for this market" before any intent. `alreadyPaid` becomes true the moment `pay` returns headers.

- `provisioning`: journal `paid` with tx, poll `seller.instance(id)` every 5 s up to 10 minutes until `status === "active"` and an IP exists; then `probePort(ip)` (default: TCP connect to 22 with a 5 s timeout, up to 12 tries 10 s apart; the test market passes a probe that returns `"not checked"` behavior by omitting the probe for 203.0.113.x). Journal `active`. Emit the `accepted` record.
- `ready`: `destroyAt = min(paidAt + need.hours * 3600, machine.expiresAt)`; a timer calls `destroy()` then. `destroy()` → `releasing` → `seller.destroy(id)` → confirm `instance(id)` is null or status destroyed → journal `released` → `released`. - `view().machine.ssh` = `ssh -i <privatePath> root@<ip>`.
